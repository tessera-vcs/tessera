# Tessera (tes): Autonomous AI Agent Protocol & Reference

> URL: https://tessera.getlunaris.dev/agents.txt | Related: https://tessera.getlunaris.dev/llms.txt | https://tessera.getlunaris.dev/llms-full.txt

Tessera (`tes`) is a multi-agent coordination layer for Git repositories (`.git/tessera`). Every commit, branch, and merge is stored as standard Git objects and refs. Tessera isolates concurrent AI coding agents and terminal sessions inside a single Git checkout, provides Copy-on-Write branch sandboxes with isolated `TES_PORT` slots and local database suffixing, and merges concurrent edits using 3-way Tree-sitter AST merging and format-preserving manifest drivers.

---

## 1. Critical Rules for AI Coding Agents

1. **NEVER run raw `git` commands** (`git status`, `git diff`, `git log`, `git branch`, `git checkout`, `git switch`, `git stash`, `git reset`, `git add`, `git commit`, `git cherry-pick`).
   - Standard Git mutates `.git/HEAD` globally across the folder and overwrites concurrent agent work.
   - Always use `tes` CLI equivalents (`tes status`, `tes diff`, `tes log`, `tes branch`, `tes switch`, `tes stash`, `tes restore`, `tes cherry-pick`, `tes pull`, `tes push`, `tes commit`, `tes merge`).
2. **Never Revert Concurrent Peer Edits**:
   - When multiple agents edit the same file on the same branch, `tes hook post-tool` automatically 3-way AST-merges their edits on disk.
   - `tes status` and `tes diff` show only your session's own changes (`Staged / Session Changes`) and list concurrent `Peer Session Changes` separately. Never delete or revert code authored by a peer session.
3. **Prefer `tes` CLI Commands in Terminal Tool Calls**:
   - Running `tes` via terminal automatically binds to your per-tab session ID (`ANTIGRAVITY_CONVERSATION_ID`, `CLAUDE_SESSION_ID`, `CODEX_THREAD_ID`, `CURSOR_TRACE_ID`, `TERM_SESSION_ID`, etc.).

## 2. Mandatory Autonomous Workflow (4 Steps)

### Step 1: Before Editing Files (Claim Intent, Branch & Paths)
```bash
tes claim [--branch <branch>] [--from <base-branch>] --intent "<concise summary of your task>" <target-file-paths...>
```
- If `--branch <branch>` is passed, Tessera automatically creates `<branch>` (if needed, optionally forked from `--from <base-branch>`) and binds your agent session to `<branch>` without changing `.git/HEAD` for the user's editor or other agents.
- If `--branch` is omitted and a claimed file already has uncommitted changes from the user or a peer session, Tessera automatically isolates your fresh session onto `agent/<session_id>` (`auto_isolate_dirty_claims = true` by default). Pass `--branch <branch>` explicitly when same-branch collaboration is intended.
- Records base file snapshots so your edits can be 3-way AST-reconciled.

### Step 2: After Editing Files (Reconcile Edits)
```bash
tes hook post-tool --path <edited-file-1> <edited-file-2>...
```
- Runs a 3-way Tree-sitter AST and structural merge against the branch state and any concurrent same-branch peer edits.
- Preserves per-branch isolation so edits on a feature branch never leak into `main`.

### Step 3: Running Builds, Tests, Linters, or Dev Servers (Execute in CoW Sandbox)
```bash
tes exec [-b <branch>] -- <command>
```
- Materializes the branch's committed + uncommitted files inside a Copy-on-Write sandbox (`clonefile` on macOS APFS, `FICLONE` on Linux Btrfs/XFS/bcachefs).
- Reuses `node_modules`, `target`, `.venv`, and `vendor` in milliseconds without extra disk space.
- Injects isolated environment variables per session slot:
  - `TES_PORT` (`3100`, `3200`, ...; `port_isolation` defaults to `false`; enable with `tes config set port_isolation true` or `TES_PORT_ISOLATION=1` to also export `PORT`, framework port variables, and POSIX CLI port-wrapper shims)
  - `TES_BRANCH` (`<branch>`)
  - `TES_DB_NAME` (`test_slot_<N>`)
  - `DATABASE_URL` / `TEST_DATABASE_URL`: NOT fabricated when unset. When a local Postgres/MySQL/network database URL is already configured in the environment or `.env*`, Tessera appends `_slot_<N>` while leaving SQLite (`sqlite:`, `file:`) and remote/cloud URLs untouched.

### Step 4: When Task Is Complete (Commit or Merge)
```bash
# Commit your session's isolated changes onto its target branch
tes commit -m "<type>(<scope>): <description>"

# Or AST-merge one or more feature branches into a target branch (e.g. main)
tes merge <branch1> [<branch2> ...] --into main -m "<commit message>"
```

## 3. Handling Conflicts, Checkpoints & Rollbacks

- **If a Conflict Is Reported**:
  - Standard Git conflict markers (`<<<<<<<`, `=======`, `>>>>>>>`) are written into the conflicted file.
  - Either edit the file to remove the conflict markers and run `tes hook post-tool --path <file>`, or resolve via CLI:
    ```bash
    tes conflicts [--json]
    tes resolve <path> --strategy <working|ast-union|ours|theirs|content> [--content <text> | --content-file <file>]
    ```
  - Never manually delete files inside `.git/tessera/`.
- **Checkpoints, Restore & Undo**:
  ```bash
  tes checkpoint <name>                  # Save a named checkpoint in the operation log
  tes restore [<rev>] [<paths...>]       # Restore branch or specific files to checkpoint/SHA/HEAD~N
  tes oplog [-n <N>]                     # View chronological operation log
  tes undo [--op <op-id> | --checkpoint <label>]  # Roll back the most recent operation or checkpoint
  ```

## 5. Model Context Protocol (MCP) Server (`tes mcp`)

When connected via MCP (`tes mcp`), the following tools, resources, and prompts are available:

### Tools
- `status`: `{ agent_id? }`
- `radar`: `{}`
- `claim`: `{ intent?, branch?, from?, symbols?, agent_id? }`
- `commit`: `{ message?, branch?, amend?, author?, co_author?, no_co_author?, verify?, agent_id? }`
- `diff`: `{ branch?, staged?, rev_range?, paths?, agent_id? }`
- `log`: `{ branch?, limit? }`
- `oplog`: `{ limit? }`
- `push`: `{ remote?, branch?, force?, tags?, dry_run?, agent_id? }`
- `pull`: `{ remote?, branch?, agent_id? }`
- `checkpoint`: `{ label, agent_id? }`
- `restore`: `{ source?, branch?, paths?, agent_id? }`
- `branch`: `{ action?: "list"|"switch"|"delete"|"rename", branch?, new_branch?, from?, force?, agent_id? }`
- `stash`: `{ action?: "push"|"pop"|"apply"|"list"|"drop"|"clear", message?, branch?, paths?, index?, agent_id? }`
- `cherry-pick`: `{ commit, branch?, agent_id? }`
- `conflicts`: `{}`
- `resolve`: `{ path, strategy: "ours"|"theirs"|"ast-union"|"working"|"content", content? }`
- `sync`: `{}`
- `undo`: `{ op?, checkpoint? }`
- `merge`: `{ agents?, into?, message?, verify?, keep_open?, dry_run?, author?, co_author?, no_co_author? }`
- `agent`: `{ action?: "list"|"close"|"clear", agent_id?, force? }`
- `config`: `{ action?: "show" }`
- `doctor`: `{}`

### Resources
- `tessera://status`: Current session status and branch state snapshot
- `tessera://radar`: Live multi-agent symbol collision radar across all active sessions
- `tessera://conflicts`: Active first-class conflicts with snippets and competing agent intents

### Prompts
- `resolve-conflicts`: Guided conflict inspection and resolution workflow
